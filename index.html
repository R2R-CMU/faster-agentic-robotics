Overview

Abstract

Robot code agents can reuse programs and execute local checks without another model call. Does separate supervision still make them faster at the same independently measured performance? We test Jev as a supervisor for skill reuse and reasoning allocation, followed by a separately registered outcome/recovery extension. Our EFE-only study treats elapsed time as primary and tokens and API-equivalent resources as secondary. An earlier Go2 development pilot exposed inactive mechanisms; it establishes no Jev benefit. Staged comparison results remain pending.

Agentic robotics · Program reuse · Reasoning allocation · Elapsed time

What remains after efficient local execution?

Skill discovery, efficient execution, and adaptive reasoning already cut repeated computation, and Jev has been studied for embodied skill execution. We ask a narrower question:

Which supervisory decisions reduce the time needed to obtain a useful controller and complete a task, once efficient native execution is available?

Fewer tokens alone do not answer it. Supervision, sensing, failed attempts and donor acquisition can cost more than the work they avoid, so they all count against the supervisor.

Two decisions first, then recovery

A library entry binds immutable code, a typed interface, preconditions, observation needs and validation provenance. Jev supplies typed proposals; common code enforces protocol, evidence and remaining-resource constraints, so an invalid or unaffordable proposal cannot bypass them.

bit 1 · Stage I

Reuse

Select a compatible library artifact and a valid invocation. Source-code adaptation needs a separately qualified interface.

bit 2 · Stage I

Reasoning allocation

Choose legal LOW or HIGH effort when the backbone is needed. Off means HIGH at every backbone call.

bit 3 · Stage II

Outcome / recovery

Supervised outcome checking and recovery. Stage I keeps the native version.

A disabled gate adds no supervisory call and withholds no library information. Exact gate activity and dispatched effort are logged, so an inactive intervention cannot support a mechanism claim.

Tasks and independence

The candidate pool is 12 Embodied First Exam (EFE) tasks: ten live/realtime and two sealed-policy. Admission targets all 12, with a floor of ten genuinely different tasks and three independent agent runs per reported condition. Native live clocks, reset limits and sealed final evaluation stay intact. This is an EFE-derived research configuration, not an official leaderboard run. Stage II readiness does not depend on a favorable Stage I ranking, and cross-agent reuse draws on identical task-disjoint donor libraries chosen before recipient outcomes are seen.

Time and performance

We report failure-inclusive elapsed time alongside independent success and native scores, with model waiting, controller execution, verification, setup, recovery and queue time separated. Failed and exhausted runs stay in; early abandonment counts as failure. Tokens and API-equivalent cost are secondary. A faster but less successful agent does not count as preserved performance.
